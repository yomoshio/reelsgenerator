# Как устроен конвейер

На входе идея, рассказ или кусок книги. На выходе вертикальный ролик и папка задачи со
всем, из чего он сделан.

## Задача — это папка

`jobs/<id>/`:

| Файл | Кто пишет | Что там |
| --- | --- | --- |
| `job.json` | все | статус, ошибка, число попыток, журнал шагов с временем и моделью |
| `source.txt` | `add` | идея или текст, как пришли |
| `plan.json` | write | замысел, герои, места, события, весь закадровый текст |
| `episode.json` | write | биты: место, кто в кадре, реплики, плашки, режиссура, карточки героев |
| `voice/beatNN.wav`, `voice/timing.json` | voice | голос бита и когда звучит каждое слово |
| `scenes/beatNN.js`, `scenes/beatNN.json` | stage | код сцены и отчёт: сколько кругов, остались ли ошибки |
| `keys/beatNN-K.png` | stage | ключевые кадры, по ним смотрит модель со зрением |
| `clips/beatNN.ass` | render | субтитры бита |
| `final.mp4`, `check.json`, `post.txt` | assemble | ролик, сверка с эталоном, текст к публикации |

Клипы битов удаляются после сборки. Ключевые кадры и код остаются, поэтому любой бит можно
переделать отдельно.

## Стадии

```
new → written → voiced → staged → rendered → assembled → approved | rejected
```

`./run.sh run` проводит стадии по очереди: сначала все задачи пишутся, потом все
озвучиваются, и так далее. Так модель остаётся загруженной, пока у неё есть работа.

| Стадия | Модель | Что делает | Проверка |
| --- | --- | --- | --- |
| write | планировщик, редактор, режиссёр | План с рассказом целиком, план переписывается, пока текст не уложится в длину стиля. Редактор правит язык, если задан. Рассказ режется на биты слово в слово, герои получают карточки куклы, режиссёр ставит каждый бит. | Код проверяет биты и режиссуру, ошибки уходят модели, до `REWRITES` раз ([stories.md](stories.md)) |
| voice | Chatterbox или Qwen3-TTS, whisper | Бит читается одним дублем голосом из `voices/narrator.wav`; кто читает, задаёт `REELSMITH_TTS`. Перед чтением Chatterbox получает текст с ударениями: их ставит RUAccent, слова из `studio/stress.txt` читаются как в списке. Что именно было прочитано, записано в `spoken` в `timing.json`. Если диктор добавил слова, дубль читается заново. Каждое написанное слово получает момент, когда его слышно. | До `RETAKES` повторов |
| stage | планировщик, кодер, зрение | Анкета сцены каждого бита: кто где стоит, что где лежит, кто что делает на каком слове. Планировщик заполняет её с нуля для каждого сценария, получая комнату такой, какой её оставил прошлый бит. Программа проверяет анкету и пишет по ней код; непрошедший бит идёт кодеру. Дальше про путь кодера: код сцены каждого бита. Движок рисует три ключевых кадра и называет ошибки. Если ошибок нет, модель со зрением отвечает на вопросы режиссёра. Всё неверное уходит кодеру. | До `ROUNDS` кругов, потом безопасная сцена ([runtime.md](runtime.md)) |
| render | — | Кадры из движка сразу в ffmpeg, туда же субтитры и звук бита. Биты рисуются параллельно. | Не начинается, если на диске меньше `MIN_FREE_GB` |
| assemble | — | Биты склеиваются, добавляются финальная карточка и музыка, громкость выравнивается до −14 LUFS, ролик сверяется с эталоном. | Итог сверки в `check.json` и в журнале |
| approve / reject | человек | `approve` кладёт ролик в `outbox/`, `reject` записывает причину. | |

Названия в верхнем регистре — строки `.env` с префиксом `REELSMITH_`, см.
[settings.md](settings.md).

## Когда что-то ломается

Ошибка в стадии оставляет задачу в её статусе, записывает причину в `job.json` и
засчитывает попытку. Следующая задача идёт дальше. После `TRIES` попыток задача получает
статус `failed`.

| Что случилось | Что делать |
| --- | --- |
| Сервер моделей недоступен, туннель упал | Поднять сервер или туннель, потом `./run.sh run`: задачи продолжатся с той стадии, где стояли |
| Задача `failed` | `./run.sh show ID` показывает причину, `./run.sh retry ID` возвращает задачу туда, где она остановилась |
| Один бит нарисован плохо | `./run.sh redo ID --beat N --note "что не так"`, затем `./run.sh run` |
| Кончается диск | Отрисовка не начнётся и скажет, сколько места свободно |
| Диктор ставит ударение не туда | Найти слово в `spoken` в `voice/timing.json`, дописать его в `studio/stress.txt` с плюсом перед ударной гласной и озвучить заново: `./run.sh retry ID --status written` |
| Голос с ошибкой в одном бите | `./run.sh retry ID --status written` озвучит заново весь эпизод |

## Что программа чинит за модель

Локальная модель ошибается в мелочах одинаково из раза в раз, и возвращать ей каждую мелочь
дорого. Поэтому мелочи чинит программа, а модели возвращается только то, что может решить
лишь она.

| Где | Что чинится само |
|---|---|
| Карточки персонажей | Ключи под другим именем берутся по порядку; очки, усы, борода, веснушки, шляпа и вещи вроде шарфа ставятся по тексту описания, а не по ответу модели; персонаж без карточки рисуется простым |
| Ответ в JSON | Незакрытые скобки в конце дописываются |
| Анкета | `round_table` становится `table`; «вещи» вроде дождя, темноты и плашек выбрасываются; вещь, которую несут, но не объявили, появляется в кармане; ссылки на то, чего нет на сцене, убираются; в комнате остаётся не больше трёх крупных предметов |
| Вещь не из каталога | Кодер один раз на выпуск рисует её сам (`scenes/props.json`); если рисунок ломает сцену, вещь рисуется простым свёртком |
| Плашки | Между битами остаются только последняя карточка правила и последний счётчик |
| Оформление места | В камере, на станции, в подвале стены остаются голыми |

Почему анкета не прошла и бит ушёл кодеру, записано в `scenes/beatNN.sheet.json`.

## Сравнение прогонов

`python tools/variant.py jobs/ID "метка"` копирует озвученное задание, чтобы поставить ту
же историю другой моделью или в другом режиме. `python tools/compare.py jobs/* --price 0.86`
печатает по строке на задание: минуты по стадиям, сколько битов прошло анкетой, сколько
написал кодер, стоимость по цене сервера.

# Как работает reelsmith

Инструкция для того, кто будет запускать конвейер на сервере с GPU и смотреть на цифры.
Английская версия с таблицей переменных и troubleshooting это `README.md`. Всё описанное
есть в коде и покрыто тестами, но ни одна модель ещё не запускалась: что проверить на
сервере, перечислено в последнем разделе.

На входе строка-идея («зомби в ночном метро»). На выходе вертикальный ролик 30–50 секунд
в папке `outbox/` и запись в базе: сколько GPU-времени он съел, какие модели его делали,
где споткнулся, как его оценили человек и площадка.

Никаких облачных API. Единственный выход в сеть: один раз скачать веса.

## 1. Что где лежит

Код устроен плоско: от команды до модели четыре шага, `cli.py` → `app.py` →
`conveyor.py` → функция стадии в `pipeline.py` → файл в `services/`.

| Файл | Что в нём |
| --- | --- |
| `models.py` | Данные: задача, сценарий, рецепт, запись о вызове, статусы. И правила на них: попытки, откаты, отказ человеком, форк. Без ввода-вывода. |
| `pipeline.py` | Стадии как функции, по порядку. Что им нужно снаружи (`Services`). Раскладка файлов задачи. Пороги ворот константами наверху. Таблица `STAGES`: какой статус берёт стадия и какой GPU-сервис ей нужен. |
| `conveyor.py` | Берёт пачку, держит карту за одним сервисом, превращает ошибки и откаты в состояние задачи. |
| `store.py` | Очередь: Postgres с арендой задач и его двойник в памяти для тестов и demo. |
| `pricing.py` | GPU-секунды на единицу для каждой модели, доллары по ставке аренды. |
| `report.py` | Цена годного ролика, пометки и GPU-часы по моделям, удержание по хукам, сравнение арм. |
| `services/` | По файлу на то, с чем конвейер разговаривает: `ollama.py` (писатель, критик, судья), `comfy.py` (графы, кадры, клипы, музыка), `voxcpm.py`, `whisper.py`, `ffmpeg.py` (план монтажа, субтитры, рендер), `outbox.py`, `synthetic.py` (заглушки всех моделей). |
| `app.py` | Собирает набор сервисов из настроек, локальный или синтетический, и запускает конвейер. Здесь же demo. |
| `cli.py` | Команды. |
| `prompts/` | Брифы писателя, критика и судьи. |

Сервисы в контейнерах: `db` (Postgres), `worker` (этот код, без GPU), `llm` (Ollama с
Qwen3.5), `comfy` (ComfyUI с Z-Image, Wan 2.2, ACE-Step), `tts` (VoxCPM2). Файлы задач
на томе `media`, готовые ролики в `./outbox/`.

## 2. Настройка

Всё в `.env` с префиксом `REELSMITH_`, полная таблица в README.

    REELSMITH_WRITER_MODEL=qwen3.5:27b     # сценарий и критик
    REELSMITH_JUDGE_MODEL=qwen3.5:27b      # судья; должна принимать картинки
    REELSMITH_LANGUAGE=ru
    REELSMITH_VOICE=narrator               # voices/narrator.wav + narrator.txt
    REELSMITH_GPU_HOUR_USD=0.99            # сколько стоит час вашей карты

    REELSMITH_IMAGE_MODEL=z-image
    REELSMITH_VIDEO_MODEL=wan-2.2
    REELSMITH_HOOK_VIDEO_MODEL=            # пусто = тот же, что VIDEO
    REELSMITH_HOOK_SHOTS=2                 # сколько первых шотов считаются хуком

Модели, которые понимает рецепт:

| Роль | Имя | Что это | GPU-секунд за единицу |
| --- | --- | --- | --- |
| image | `z-image` | ComfyUI, `keyframe.json`, Z-Image Turbo | 10 за кадр |
| video | `wan-2.2` | ComfyUI, `animate.json`, Wan 2.2 14B, 16 fps | 48 за секунду клипа |
| video | `wan-5b` | ComfyUI, `animate-draft.json`, Wan 2.2 5B, 24 fps | 12 за секунду клипа |

Писатель, критик и судья это всегда `ollama`, голос всегда `voxcpm`, музыка всегда
`ace-step`: у этих ролей одна реализация, выбирать нечего. Три графа ComfyUI обязательны,
без них worker не стартует и называет файл. `animate-draft.json` опционален: когда он
есть, появляется модель `wan-5b`.

Секунды в правой колонке это допущения из исследования для RTX 5090; после первой недели
на карте заменить своими замерами, таблица в `pricing.py`. Пороги ворот и число попыток
это константы наверху `pipeline.py`, а не настройки: их никто не крутит под деплой.

Рецепт для одной задачи задаётся при добавлении и дальше не меняется:

    reelsmith add "идея" --video wan-5b --hook-video wan-2.2

## 3. Путь одной задачи

    new → scripted → voiced → painted → framed → animated → checked → scored → assembled
                                                                                  │
                                                                 (человек: approve / reject)
                                                                                  ▼
                                      approved → published → (человек: measure) → measured

Worker берёт пачку задач (по умолчанию 6) и ведёт её **по стадиям, а не по задачам**:
сначала все получают сценарий, потом все голос, и так далее. Каждая стадия ходит ровно в
один GPU-сервис, и перед её началом предыдущий сервис просят выгрузиться: одна карта на
32 ГБ не вмещает LLM, TTS и Wan одновременно. Поэтому судья получил свои стадии `pick` и
`check` между стадиями ComfyUI, а не вызывается посреди них.

| Стадия | Берёт | GPU | Что делает | Ворота |
| --- | --- | --- | --- | --- |
| write | new | Ollama | Писатель возвращает заголовок, хук и его тип, персонажей с внешностью, 3–10 шотов (реплика, стоп-кадр, движение, кто в кадре), бриф музыки. Критик ставит оценку. | ниже 7: переписать с замечаниями, до двух раз; остаётся лучший вариант |
| voice | scripted | TTS | По файлу на реплику. Длина записи плюс 0,35 с становится длиной шота, от 2 до 8 с. Поэтому голос раньше картинок: длину ролика задаёт речь. | |
| paint | voiced | ComfyUI | Два кандидата на шот из внешности персонажей, описания кадра и общего стиля. | |
| pick | painted | Ollama | Vision-модель выбирает один кандидат на шот. | |
| animate | framed | ComfyUI | Клип на шот из его кадра; первые `hook_shots` могут идти на другую модель. Шоты, у которых клип уже есть, пропускаются. Seed включает номер попытки. | |
| check | animated | Ollama | Четыре стоп-кадра каждого клипа идут судье. | ниже 6: клип удалён, задача назад в `framed`; после трёх попыток шота клип остаётся как есть |
| score | checked | ComfyUI | Музыка на длину ролика плюс 2 с. Делается один раз, откаты её не трогают. | |
| assemble | scored | Ollama | ffmpeg: клипы по длине реплик, 1080×1920 и 30 fps, голос поверх приглушённой музыки с сайдчейном, субтитры по три слова. Восемь стоп-кадров результата идут судье. | ниже 7: плохие шоты удалены, задача назад в `framed` |
| approve / reject | assembled | | Человек. `reject` удаляет все клипы и откатывает. | |
| publish | approved | | Ролик и `post.json` в outbox. Загружает человек. | |
| measure | published | | `reelsmith measure` вносит цифры площадки руками. | |

Файлы задачи лежат в `/data/media/<id>/`: `voice/00.wav…`, `frames/00-0.png, 00-1.png…`,
`clips/00.mp4…`, `stills/00/… stills/final/`, `music.flac`, `subtitles.ass`, `final.mp4`.
Пути в базе относительные, том можно перенести.

## 4. Когда что-то ломается

Любой откат и любая ошибка внутри стадии считаются попыткой. После `MAX_ATTEMPTS` (по
умолчанию 5) задача получает статус `failed`, причина в `last_error`. Её затраты всё равно
входят в цену годного ролика.

| Что случилось | Что делает конвейер |
| --- | --- |
| Клип с артефактами | Удалить, откат в `framed`, перерисовать с новым seed. На третьей попытке шота клип остаётся. |
| Финал не прошёл QA | Откат в `framed`, перерисовать плохие шоты. |
| Человек нажал `reject` | То же, что QA, только удаляются все клипы. |
| ComfyUI вернул ошибку, граф не уложился в таймаут, Ollama ответила не по схеме, в рецепте неизвестная модель | Задача остаётся в своём статусе, попытка +1, вызов записан как `failed`. |
| Ошибка не из стадии: баг, упавшая база | Процесс завершается, docker его поднимает, аренда задач истекает через 45 минут. |
| Экспортированный граф без нужных слотов | Worker отказывается стартовать и называет граф и слот. |

## 5. A/B: та же идея, другая модель

    reelsmith add "зомби в ночном метро" "пациент, который не спит"
    reelsmith work --once                   # хотя бы до framed
    reelsmith fork <id> --video wan-5b --arm B

Форк копирует сценарий, голоса и кадры, а клипы, музыку и финал сбрасывает: обе армы
анимируют один и тот же кадр. Родитель получает метку эксперимента и арму `A`.
Затраты родителя до форка копируются с пометкой `shared`: `compare` считает их в обеих
армах, чтобы цена ролика была сопоставима, `report` считает один раз.

Когда обе армы собраны: оценить вслепую (`rate`), опубликовать, через сутки внести
метрики (`measure`), сравнить. Вывод demo на трёх идеях:

    arm  videos  good  usd   per video  per good  qa    flagged  rating  ret3s
    A    3       3     1.61  0.54       0.54      8.50  6        6.67    0.51
    B    3       3     0.65  0.22       0.22      8.50  4        7.33    0.49

Колонки: роликов, дошли до одобрения, цена, за ролик, за годный ролик, средняя оценка
QA, помеченных клипов, средняя слепая оценка, удержание на третьей секунде. В demo
оценки и удержание синтетические, таблица показывает форму, а не вывод.

## 6. GPU-время и отчёт

Каждый вызов модели записывается на задачу: стадия, модель, единицы (кадры, секунды
клипа, символы, вызов), GPU-секунды по тарифу и доллары по ставке аренды, исход (`ok`,
`flagged`, `failed`), номер шота, время по часам. Единицы считаются так, как генерирует
модель: Wan округляет до 4k+1 кадров.

`reelsmith report` по всем задачам, вывод того же demo:

    videos 6  good 6  failed 0  pending 0
    spent $2.04  cost per good $0.34  qa pass rate 1.00  gpu hours 2.06
    model     calls  flagged  flag rate  usd   gpu hours
    wan-2.2   27     6        0.22       1.06  1.07
    ollama    143    0        0.00       0.59  0.60
    wan-5b    22     4        0.18       0.21  0.22
    z-image   36     0        0.00       0.10  0.10
    ace-step  6      0        0.00       0.07  0.07
    voxcpm    18     0        0.00       0.01  0.01
    hook     videos  retention 3s  completion
    promise  2       0.51          0.30
    threat   4       0.50          0.30

Цена годного ролика включает проваленные задачи. Строки моделей отсортированы по
GPU-часам: сразу видно, кто ест карту. Удержание по типу хука отвечает на вопрос «какие
хуки писать».

## 7. Прогон без моделей

`reelsmith demo --ideas 3 --out demo` (или `make demo`) прогоняет всё на заглушках:
сценарии из заготовленных реплик, кадры и клипы это цветные заливки от ffmpeg, голос и
музыка это тоны. Монтаж, субтитры, стоп-кадры, outbox и учёт настоящие. Каждая идея
форкается в арму B на `wan-5b`, собранные ролики одобряются автоматически, оценки
случайные и так и подписаны. Судья помечает 20 % клипов и заворачивает 15 % финалов,
поэтому видно, как повторы и откаты попадают в цену. Три идеи занимают около 40 секунд.

`REELSMITH_SERVICES=synthetic` делает то же внутри настоящего worker с настоящей базой:
так проверяется развёртывание до того, как скачаны веса. Тот же сценарий идёт как тест:
`make test`.

## 8. Команды

| Команда | Что делает |
| --- | --- |
| `reelsmith migrate` | применяет миграции |
| `reelsmith add ИДЕЯ... [--image M] [--video M] [--hook-video M] [--experiment X --arm A]` | ставит задачи в очередь |
| `reelsmith work [--once] [--stages write,voice,...]` | крутит конвейер |
| `reelsmith status` | задачи по статусам |
| `reelsmith approve ID` / `reject ID [--reason ...]` / `rate ID 1..10` | решения человека |
| `reelsmith fork ID [--arm B] [--video M]` | вторая арма на тех же кадрах |
| `reelsmith measure ID --views N --retention-3s X --completion Y` | цифры площадки |
| `reelsmith compare EXPERIMENT` / `report` | таблицы |
| `reelsmith demo [--ideas N] [--arm-a M] [--arm-b M] [--out DIR]` | прогон на заглушках |

Внутри compose: `docker compose run --rm worker <команда>`.

## 9. Что остаётся проверить на сервере

- Графы ComfyUI: `keyframe.json`, `animate.json`, `score.json` и опциональный
  `animate-draft.json` экспортируются руками по `workflows/README.md`.
- Qwen3.5 как судья: различает ли артефакты и держит ли порог. Если нет,
  `REELSMITH_JUDGE_MODEL` меняется на любую vision-модель в Ollama.
- Тарифы в `pricing.py`: заменить допущения замерами.
- Голос: `voices/narrator.wav` и `narrator.txt` для клонирования, качество русского у VoxCPM2.

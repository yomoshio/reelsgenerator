# Как устроен конвейер

На входе строка-идея. На выходе вертикальный ролик в `outbox/` и запись в базе: какие
модели его делали, сколько GPU-времени ушло, где он споткнулся и как его оценили.

## Где что лежит

От команды до модели четыре шага: `cli.py` → `app.py` → `conveyor.py` → функция стадии в
`pipeline.py` → файл в `services/`.

| Путь | Что там |
| --- | --- |
| `src/reelsmith/models.py` | Данные: задача, сценарий, рецепт, запись о вызове модели, статусы, и правила на них: попытки, откаты, отказ человеком, A/B-форк. Без ввода-вывода. |
| `src/reelsmith/pipeline.py` | Стадии по порядку, что им нужно снаружи (`Services`), пороги проверок (`Gates`), таблица `STAGES`. |
| `src/reelsmith/conveyor.py` | Берёт пачку задач, держит видеокарту за одним сервисом, превращает ошибки и откаты в состояние задачи. С `GPU_SHARED=1` делит стадии на две линии, которые работают одновременно: ComfyUI (кадры, клипы, музыка) и всё остальное; каждая линия выгружает только свои модели и только на паузе. |
| `src/reelsmith/store.py` | Очередь в Postgres с арендой задач, и её копия в памяти для тестов. |
| `src/reelsmith/styles.py` | Загрузка и проверка стилей из `styles/`. |
| `src/reelsmith/pricing.py` | GPU-секунды на единицу работы каждой модели, по замерам. |
| `src/reelsmith/report.py` | Цена годного ролика, брак и GPU-часы по моделям, удержание, сравнение A/B. |
| `src/reelsmith/services/` | По файлу на каждый внешний сервис: `ollama.py`, `comfy.py`, `voxcpm.py`, `whisper.py`, `ffmpeg.py` (монтаж, субтитры, плашки), `outbox.py`, `synthetic.py` (заглушки). |
| `src/reelsmith/settings.py` | Всё, что читается из `.env`. |
| `src/reelsmith/series.py` | Синопсис в серию: дуга сезона, план каждого выпуска, файлы `.md` и `.txt`; разбор файлов идей. |
| `src/reelsmith/books.py` | Готовый рассказ или книга в серию: чтение `.txt`, `.fb2`, `.epub`, пересказ кусками по событиям, деление событий на выпуски там, где поворачивает история, план выпуска строго из его событий. |
| `src/reelsmith/studio.py` | Заявки от блоков ComfyUI из `studio/inbox`, файл статуса `studio/status.txt`, пауза. |
| `comfy_nodes/reelsmith/` | Блоки Reelsmith для редактора ComfyUI: ролик, серия, статус, одобрить, пауза. |
| `src/reelsmith/prompts/` | Общие части промптов писателя, критика и судьи; остальное приходит из стиля. |
| `services/tts/` | Сервис голоса на VoxCPM2 и `design_voice.py`, который делает голос по описанию. |
| `workflows/` | Схемы ComfyUI, которые пишет `scripts/make_graphs.py`. |
| `styles/` | Стили каналов. |
| `studio/` | Всё, что делается в ComfyUI руками, и файл идей. |
| `scripts/` | Установка хоста, управление сервером, скачивание весов, генерация схем. |

Сервисы в контейнерах: `db` (Postgres), `worker` (этот код, без видеокарты), `llm`
(Ollama), `comfy` (ComfyUI), `tts` (VoxCPM2).

## Путь одной задачи

```
new → scripted → voiced → painted → framed → animated → checked → scored → assembled
                                                                              │
                                                       человек: approve или reject
                                                                              ▼
                                     approved → published → человек: measure → measured
```

Воркер берёт пачку задач, по умолчанию шесть, и ведёт её по стадиям, а не по задачам:
сначала все получают сценарий, потом все голос, и так далее. Каждая стадия ходит ровно в
один сервис с видеокартой, и перед её началом предыдущий сервис просят выгрузиться. Одна
карта не вмещает языковую модель, голос и Wan одновременно, поэтому у судьи свои стадии
`pick` и `check` между стадиями ComfyUI.

| Стадия | Берёт | Сервис | Что делает | Проверка |
| --- | --- | --- | --- | --- |
| write | new | Ollama | Сначала планировщик делает из идеи, фразы или рассказа, план выпуска: героев с внешностью, 8–12 событий по порядку, заложенную деталь и последнюю фразу. Потом писатель раскладывает план на шоты (реплика, кадр, движение, движется ли что-то, ударные слова, плашки) и пишет бриф музыки. Критик сверяет сценарий с планом и ставит оценку. Код проверяет то, что видно без модели (список ниже). | ниже `SCRIPT_PASS` или есть замечание кода: переписать, до `REWRITES` раз; план не меняется; остаётся лучший вариант |
| voice | scripted | TTS, Whisper | Соседние реплики читаются одним дублем до `PASSAGE_WORDS` слов, в модель идёт только их текст. Whisper слушает дубль: если диктор добавил слова, которых нет в репликах, дубль озвучивается заново; иначе дубль режется на шоты посередине пауз между репликами. Длина куска становится длиной шота, у последнего шота дубля плюс 0,35 с. Голос идёт раньше картинок, потому что длину ролика задаёт речь. | после `VOICE_TRIES` неудачных дублей одной реплики |
| paint | voiced | ComfyUI | `CANDIDATES` кадров на шот из внешности персонажей, описания кадра и `[look].frame` стиля. С `CAST_IMAGE_MODEL=qwen-edit` сначала рисуется портрет каждого героя, файл назван по его внешности и стилю, поэтому в следующих выпусках серии портрет тот же; кадры с героем рисует Qwen-Image-Edit по портрету первого героя в кадре. | |
| pick | painted | Ollama | Судья выбирает один кадр на шот. | |
| animate | framed | ComfyUI | Клип на шот из выбранного кадра. Шоты, где что-то движется, идут в `VIDEO_MODEL`, спокойные в `CALM_VIDEO_MODEL`, первые шоты-хук могут идти в `HOOK_VIDEO_MODEL`. `still` это медленный наезд камеры через ffmpeg. Шоты, у которых клип уже есть, пропускаются; seed меняется с каждой попыткой. | |
| check | animated | Ollama | Четыре стоп-кадра каждого клипа идут судье. | ниже `CLIP_PASS`: клип удалён, задача назад в `framed`; после `CLIP_TRIES` попыток шота клип остаётся |
| score | checked | ComfyUI | Музыка на длину ролика плюс 2 с, один раз. | |
| assemble | scored | Ollama | ffmpeg: клипы по длине реплик, 1080 × 1920, 30 кадров/с, голос поверх приглушённой музыки, субтитры и плашки стиля. Восемь стоп-кадров итога идут судье. | ниже `QA_PASS`: плохие шоты удалены, задача назад в `framed` |
| approve или reject | assembled | | Решает человек. `reject` удаляет все клипы и возвращает задачу в `framed`. | |
| publish | approved | | Ролик и `post.json` в `outbox/`. Загружает человек. | |
| measure | published | | Цифры площадки вносятся командой `measure`. | |

Названия в верхнем регистре это строки `.env` с префиксом `REELSMITH_`, см.
[settings.md](settings.md).

Файлы задачи лежат в томе `media`, в папке `<id>/`: `voice/`, `frames/`, `clips/`,
`stills/`, `music.flac`, `subtitles.ass`, `final.mp4`. Пути в базе относительные.

## Блоки ComfyUI

Блоки Reelsmith в редакторе ничего не рисуют сами. Каждый кладёт заявку в
`studio/inbox` и сразу завершается: конвейеру нужна та же очередь ComfyUI, и блок, который
ждал бы ролик, остановил бы её. Воркер перед каждым кругом забирает заявки: ролик, серия,
одобрение, пауза. Ответ на каждую он пишет рядом в `studio/inbox/done`, а сводку последних
задач в `studio/status.txt`, её показывает блок «Статус». Каждый собранный ролик копируется
в `studio/output/reelsmith/videos`, это папка вывода ComfyUI, поэтому ролик сам появляется
в Ассетах. Пока стоит пауза, воркер принимает заявки, но шагов не делает и держит
видеокарту свободной.

## Текст на экране

Писатель для каждого шота выбирает ударные слова и плашки: баннер правила, подпись к
предмету, карточку с именем. Всё это рисует ffmpeg поверх клипа, картиночная модель текст
не рисует. Поэтому кириллица всегда правильная, а в кадрах букв нет.

Субтитры в стилях с караоке подсвечивают слово, которое звучит сейчас; ударные слова
крупнее. Подпись не переходит через склейку. Текст субтитров берётся из сценария, как он
написан; распознавание речи даёт только моменты, когда звучит каждое слово, поэтому числа
не превращаются в цифры. Если распознавание услышало слово иначе («20» вместо
«двадцать»), написанное слово занимает время услышанного, а паузы остаются на месте.

Плашка появляется только после того, как диктор произнёс её слова: цель с того шота, где
её назвали, число на счётчике в том же шоте, где оно прозвучало. Плашку, которая
опережает голос, сборка не показывает. Цвета, шрифт и места плашек задаёт стиль:
[styles.md](styles.md).

## Что проверяет код в сценарии

После критика сценарий проверяет код, без модели. Каждое найденное замечание уходит
писателю на переписывание вместе с замечаниями критика:

- заголовок, реплика или плашка написаны не на языке канала (`REELSMITH_LANGUAGE`):
  большинство слов не из его алфавита. Промпты по-английски, внешность героев и картинки
  тоже, и без этой проверки модель писала по-английски каждую третью серию. Проверяются
  русский, украинский, белорусский и английский;
- ролик, прочитанный вслух, выйдет длиннее или короче границ `seconds` стиля. Длина
  считается по слогам при темпе 5 слогов в секунду: whisper намерил у диктора 5,4, запас
  оставлен на медленные реплики перед поворотом;
- число событий и пауз не совпадает с `events` и `breaths` стиля, первые два шота или
  последний не события, или две паузы идут подряд;
- движущихся шотов больше, чем разрешает `moving` стиля;
- плашка показывает слова, которых диктор ещё не сказал;
- реплика называет героя, а в `cast` его нет. Такой герой всё равно попадает в промпт
  кадра со своей внешностью, но писатель получает замечание;
- в `motion` есть панорама, наклон или проезд камеры: видеомодель дорисует то, чего нет
  в кадре, и обычно это люди или существа;
- подряд больше `empty_shots` шотов без героя в кадре;
- `picture`, `motion` или внешность героя написаны не по-английски.

Видеомодели к каждому описанию движения дописывается, что новых людей в кадре не
появляется, а в пустом кадре никто не появляется вовсе. Негативный промпт для этого не
годится: граф Wan работает с cfg 1, и негатив не учитывается.

## Когда что-то ломается

Любой откат и любая ошибка в стадии считаются попыткой. После `MAX_ATTEMPTS` задача
получает статус `failed`, причина в `last error`. Её расходы всё равно входят в цену
годного ролика.

| Что случилось | Что делает конвейер |
| --- | --- |
| Клип с артефактами | Удаляет клип, откат в `framed`, новый seed. После `CLIP_TRIES` попыток шота клип остаётся. |
| Итог не прошёл проверку | Откат в `framed`, переделываются плохие шоты. |
| Человек нажал `reject` | То же, только переделываются все клипы. |
| Ошибка ComfyUI, таймаут, ответ Ollama не по схеме | Задача остаётся в своём статусе, попытка засчитана, вызов записан как `failed`. |
| Ошибка не из стадии: баг, упала база | Процесс завершается, Docker его поднимает, аренда задач истекает через `LEASE_MINUTES`. |
| Схема ComfyUI без нужных слотов | Воркер не стартует и называет схему и слот. |

## A/B: та же идея, другая модель

```
reelsmith add "зомби в ночном метро"
reelsmith fork <id> --video wan-5b --arm B
```

Форк копирует сценарий, голос и кадры, а клипы, музыку и итог сбрасывает: обе ветки
оживляют один и тот же кадр. Расходы родителя до форка копируются с пометкой `shared`:
`compare` учитывает их в обеих ветках, чтобы цены были сопоставимы, `report` один раз.
Форк с другим стилем меняет только субтитры, плашки, хвост описания движения и то, как
судит судья: сценарий и кадры общие.

Демо на трёх идеях, на заглушках, поэтому оценки и удержание выдуманные:

```
arm  videos  good  usd   per video  per good  qa    flagged  rating  ret3s
A    3       3     0.58  0.19       0.19      8.50  6        9.00    0.43
B    3       3     0.41  0.14       0.14      8.50  6        6.33    0.49
```

Колонки: роликов, дошли до одобрения, потрачено, за ролик, за годный ролик, средняя
оценка судьи, забракованных клипов, средняя слепая оценка человека, удержание на третьей
секунде.

## Деньги и GPU-время

Каждый вызов модели записывается на задачу: стадия, модель, единицы работы (кадры,
секунды клипа, символы, вызовы), GPU-секунды по таблице в `pricing.py`, доллары по
`GPU_HOUR_USD`, исход (`ok`, `flagged`, `failed`), номер шота. `reelsmith report`:

```
videos 6  good 6  failed 0  pending 0
spent $0.86  cost per good $0.14  qa pass rate 1.00  gpu hours 1.05
model     calls  flagged  flag rate  usd   gpu hours
ollama    124    0        0.00       0.42  0.52
wan-2.2   26     6        0.23       0.24  0.30
...
```

Цена годного ролика включает проваленные задачи. Модели отсортированы по GPU-часам.
Таблица `pricing.py` измерена на RTX 4090 48 ГБ при настройках по умолчанию; на другой
карте или с большими клипами её стоит перемерить, время каждого задания видно в очереди
ComfyUI.

## Прогон без моделей

`./run.sh demo` гоняет весь конвейер на заглушках: сценарии из заготовленных реплик, кадры и
клипы это цветные заливки, голос и музыка это тоны. Монтаж, субтитры, плашки, учёт и
outbox настоящие. Каждая идея форкается во вторую ветку, судья бракует часть клипов и
итогов, поэтому видно, как переделки попадают в цену. Три идеи считаются меньше минуты.

`REELSMITH_SERVICES=synthetic` делает то же в настоящем воркере с настоящей базой: так
можно проверить установку до того, как скачаны веса.

## Команды воркера

`./run.sh` и `./run.sh server` вызывают эти команды, напрямую они нужны редко:
`docker compose run --rm worker <команда>`.

| Команда | Что делает |
| --- | --- |
| `migrate` | создаёт таблицу задач |
| `add ИДЕЯ... [--style S] [--image M] [--video M] [--hook-video M]` | ставит идеи в очередь |
| `queue ФАЙЛ [--style S]` | ставит идеи из файла и помечает строки |
| `series ФАЙЛ [--episodes N] [--name ИМЯ] [--style S]` | синопсис в серию: `ИМЯ.md` и `ИМЯ.txt` в `studio/series` |
| `work [--once] [--stages write,voice,...]` | крутит конвейер |
| `status`, `jobs [--status S]` | счётчики по статусам, список задач |
| `approve ID`, `reject ID [--reason ...]`, `rate ID 1..10` | решения человека |
| `retry ID [--status S]` | вернуть упавшую или зависшую задачу в работу, сделанное сохраняется |
| `fork ID [--arm B] [--video M] [--style S]` | вторая ветка на тех же кадрах |
| `measure ID --views N --retention-3s X --completion Y` | цифры площадки |
| `compare ЭКСПЕРИМЕНТ`, `report` | таблицы |
| `styles`, `preview СТИЛЬ` | стили и кадр с их субтитрами и плашками |
| `smoke [--out DIR]` | по одному вызову каждой модели с временем: проверка новой машины |
| `demo [--ideas N] [--style S]` | прогон на заглушках |

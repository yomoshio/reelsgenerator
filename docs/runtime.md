# Движок отрисовки

Каждый бит рисует код, который пишет модель. Код запускается в движке `runtime/`: это
Node и skia-canvas, видеокарта не нужна. Код модели только объявляет, что происходит:
место, вещи, люди, кто куда идёт и на каком слове, камера, свет и приёмы. Каждый кадр
движок считает сам из этих объявлений. Поэтому движение плавное, а между кадрами ничего
не меняется без причины.

## Что рисует движок, а что модель

| Рисует движок | Решает код модели |
| --- | --- |
| Кукла каждого героя по его карточке, позы, ходьба, дыхание | Где стоит герой, куда идёт, когда садится, тянется, показывает |
| Места: комната, магазин, лестница, разрез дома, улица, открытое место | Какое место и где в нём свет |
| Вещи: дверь, окно, кровать, банкомат, стеллаж, вода и вещи из библиотеки | Какие вещи и где они стоят, когда меняют состояние |
| Плашки и весь текст на экране | Ничего: текст рисуют только плашки из сценария |
| Приёмы: линза, волны звука, пунктир, маршрут, счётчик, разрез дома | Какой приём, на что и с какого слова |

Вещи всегда стоят на полу или на ступенях, а оконные висят на стене. Мелкая вещь может
стоять на другой: подсвечник на столе, телефон на прилавке (`on: table`). Висеть в воздухе
вещь не может. Камера никогда не показывает край декорации.

## Библиотека вещей

`library/things/` — плоские силуэты в SVG, которые движок перекрашивает в палитру стиля.
`./install.sh` наполняет её силуэтами game-icons.net, их около четырёх тысяч: украшения,
мебель, инструменты, экипажи, здания. Режиссёру показываются не все, а только те, чьи
названия встречаются в описаниях мест и героев эпизода, не больше сорока.

Иконки идут под CC BY 3.0. Если ролик их показывает, авторы попадают в `post.txt`, и
подпись нужно оставить в описании публикации.

Вещь, которой нет в библиотеке, можно нарисовать один раз любой картиночной моделью на
светлом фоне и перевести в силуэт:

```
.venv/bin/pip install vtracer
.venv/bin/python scripts/vectorize.py платье.png ball_gown "a ball gown of the 1880s"
```

Сначала посмотрите на `library/things/ball_gown.svg`. После этого платье рисуется кодом, одинаково в
каждом ролике.

## Песочница

Код модели работает в отдельном контексте: без `require`, без `process`, без `eval`.
На саму сцену даётся 2 с, на каждый вызов рисования — 0,25 с, памяти — 512 МБ.

Сам Node запускается с ограничением прав:
- читать можно только движок, библиотеку вещей и стили;
- писать можно только в папку ключевых кадров задачи;
- запускать процессы нельзя.

Сеть движок не ограничивает. Код пишет своя модель на своей машине, но на чужих моделях
это стоит помнить.

## Проверки кадра

Движок рисует три ключевых кадра бита и сам находит ошибки. Каждая ошибка уходит модели
одной фразой по-английски:

- в бите есть герой, которого сцена не поставила;
- режиссёр назвал вещь, а сцены её нет;
- плашка привязана к тому, чего нет на сцене;
- сцена дольше 5 с, и в ней ничего не происходит;
- вещь или человек висит в воздухе, проваливается или почти весь за краем кадра;
- две вещи стоят друг в друге, два человека слиплись;
- плашка закрывает человека;
- кадр почти чёрный или слишком светлый для канала;
- слово, на котором что-то должно случиться, в бите не звучит. Ошибка перечисляет все
  слова бита.

## Запуск руками

```
cd runtime && npm ci            # один раз
npm test                        # тесты движка
```

Вход движка — JSON на stdin, его собирает `reelsmith.runtime.scene_input`. В режиме `keys`
движок пишет PNG ключевых кадров и печатает отчёт. В режиме `frames` он отдаёт сырые кадры
RGBA 1080×1920 в ffmpeg.
